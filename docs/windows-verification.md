# Windows 11 x64 수동 검증 — BLOCKED

2026-10-11: 선택된 환경은 Debian Linux입니다. 실제 Windows 환경, 두 Windows PC, 설치기 v1/v2, 서명 인증서가 없습니다. 아래 항목은 **미실행**이며 Linux 테스트 통과나 번들 생성으로 완료 처리하지 않습니다.

## 승인된 Windows 시험 환경에서 실행할 순서

1. 깨끗한 Windows 11 x64 시험 VM과 두 번째 Windows 인스턴스, 별도 Windows 사용자 A/B를 준비합니다. 환경 사용 허용 여부를 확인합니다.
2. `npm ci`, `npx playwright install chromium`, 시험 PostgreSQL/Keycloak 실행, 전체 테스트, `npm run make:win`을 수행합니다. 시험 fixture를 운영 인증으로 재사용하지 않습니다.
3. v1 설치기의 SHA-256, 커밋, Node/npm/Electron/Windows 빌드 번호, 서명 여부를 기록합니다. 미서명 시험본이라면 명시하고 Windows 경고를 자동 우회하지 않습니다.
4. 새 설치 → 실행 → 시스템 브라우저 로그인 → 프로젝트/작업 생성 → 두 PC 조회/동시 수정 → 충돌 선택을 검증합니다. 저장 확인 전에는 저장됨 표시가 없어야 하고 활성 화면은 10초 안에 조회를 시작해야 합니다.
5. 작업명 한글 조합, 날짜 양끝/윤년, null/0/100 진행률, 표/막대/양 끝 조절, Esc, 키보드, 100/125/150/200% 화면 배율을 검증합니다.
6. 저장 전·전송 중·커밋 뒤 응답만 유실되는 장애를 각각 주입합니다. 편집이 즉시 잠기고 미저장 초안이 남아야 합니다. 초안 보호 저장 완료 후 프로세스 강제 종료 → 재로그인 → 복구 및 중복 적용 방지를 검증합니다.
7. Windows 사용자 A의 DPAPI 파일을 B로 복사해 복호화되지 않는지 확인합니다. 같은 Windows 사용자 안의 앱 계정 전환에서도 다른 계정 초안이 노출되면 안 됩니다. OS 사용자와 같은 권한의 다른 프로그램까지 DPAPI가 차단한다고 주장하지 않습니다.
8. v2(버전 증가, 고정 앱 ID 유지) 설치기를 생성해 v1 위에 수동 업데이트합니다. 서버 데이터와 보호 초안이 유지되는지 확인합니다. 자동 업데이트 서비스는 없습니다.
9. 앱 제거 후 서버 데이터가 남는지 확인하고 재설치·재로그인 후 다시 조회합니다. 로컬 초안 제거/유지 결과도 실제 설치기 동작에 따라 기록합니다.
10. `npx tsx scripts/verify-windows.ts`로 산출물 체크섬을 기록하고 아래 실제 결과를 채웁니다.
